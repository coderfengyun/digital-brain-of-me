# Skill 设计的三个 Pattern

> status: draft
> related_idea: task-20260325-001
> created_at: 2026-03-27

---

## 需求

越来越多人在用 Claude Code / Cursor 的 Skill 来封装重复性工作。但一个关键问题是：**怎么把专家脑袋里的知识变成一个好用的 Skill？**

这不是写一段 prompt 就完的事。Skill 的质量取决于你能从专家那里提取多少隐性知识，以及这些知识能不能被结构化地表达出来。

我最近观察到三种不同的 Skill 设计 Pattern，分别适合不同的场景。

---

## Pattern 1: 访谈提取模式

**一句话描述**：找一个毫无背景的人跟专家做访谈，把访谈转录为 Skill。

**流程**：
```
毫无背景的人 + 专家
↓
访谈：问清楚每一个动作背后的思考和逻辑
↓
将访谈转录为文本
↓
跟大模型一起，从文本中构建专家的 Skill
```

**核心点在于**：访谈者"毫无背景"恰恰是优势——他会问出专家觉得"这不是常识吗？"的问题。这些"常识"往往就是 Skill 里最关键的隐性知识。

**适用场景**：专家不擅长自我表达，或者知识太内化以至于说不出来。

---

## Pattern 2: 专家迭代模式

**一句话描述**：专家自己跟 AI 协作，通过对比初级版本和专家版本来提取 Skill。

**流程**：
```
Step1: 只给目标，让 AI 生成初级版本（版本A）
↓
Step2: 专家跟 AI 一起 loop，调整到符合专家标准的版本（版本B）
↓
Step3: 将版本A、版本B、整个对话历史交给 AI
↓
Step4: AI 总结 Skill，不确定的部分由 AI 启动对专家的访谈
```

**核心点在于**：版本A → 版本B 的 diff 就是专家知识。AI 不需要从零理解专家——它只需要看"专家改了什么"。

**适用场景**：专家自己有动力去打磨产出，且能投入时间跟 AI 协作。

---

## Pattern 3: Diff 反馈循环模式

**一句话描述**：AI 写初稿，人改到满意，脚本自动 diff 两版提取规则写回 Skill，形成自动改进循环。

> 来源：Jason Zuo (@xxx111god) 的 [writing style skill 实践](https://x.com/xxx111god/status/2036565921788207245)

**流程**：
```
AI 用当前 Skill 写初稿
↓
人改到满意（中间改几轮不管，只比较首尾两版）
↓
脚本自动 diff 两版
↓
提取「人改了什么」→ 转化为规则
↓
规则写回 Skill → 下次更准
```

**核心点在于**：这是一个**持续自动化**的过程。不是一次性提取知识，而是每次使用都在积累规则。Jason Zuo 的 writing style skill 用这套机制自动积累了 48 条规则、740 行，没有一条是手写的。

**和 Pattern 2 的区别**：Pattern 2 是一次性的"版本A vs 版本B"对比，Pattern 3 是持续运行的反馈循环——每次用 Skill 都在改进它。

**适用场景**：Skill 需要长期使用和持续改进，且使用者愿意在每次使用后花时间修改输出。

---

## 三个 Pattern 的对比

| 维度 | Pattern 1: 访谈提取 | Pattern 2: 专家迭代 | Pattern 3: Diff 反馈循环 |
|------|---------------------|---------------------|-------------------------|
| 参与者 | 访谈者 + 专家 + AI | 专家 + AI | 使用者 + AI + 脚本 |
| 知识来源 | 访谈转录 | 版本对比 + 对话历史 | 持续的 diff 积累 |
| 一次性 vs 持续 | 一次性 | 一次性 | 持续改进 |
| 自动化程度 | 低 | 中 | 高 |
| 适合阶段 | Skill 从 0 到 1 | Skill 从 0 到 1 | Skill 从 1 到 N |

---

## 从效果上看

这三个 Pattern 不是互斥的，而是可以组合的：

1. 用 **Pattern 1 或 2** 完成 Skill 的冷启动（从 0 到 1）
2. 用 **Pattern 3** 实现 Skill 的持续进化（从 1 到 N）

Skill 设计的核心难题始终是同一个：**怎么把人脑中的隐性知识变成 AI 可执行的显性规则**。三个 Pattern 分别从不同角度切入这个问题——访谈、对比、和持续反馈。
