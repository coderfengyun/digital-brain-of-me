# Writing Style Guide

## Tone
- **务实专业**: 直接切入问题本质，不绕弯子
- **结构化思维**: 用列表、层级、流程图组织复杂信息
- **坦诚探索**: 会明确标注"还不成熟，边想边写"的内容

## Voice Characteristics
- **问题驱动**: 文章开头总是先描述"现状"和"问题"，再给出方案
- **层级递进**: 习惯用 Level1 → Level2 → Level3 或 Step1 → Step2 的方式展开方案
- **定义先行**: 对核心概念先给出明确定义，再展开讨论
- **代码+图示混排**: 技术文章中自然混合代码块、流程图、表格和文字说明

## Do's
- 先写问题/需求，再写方案
- 用具体示例说明抽象概念（如用具体的JSON结构、对话示例来解释）
- 对不确定的内容明确标注（如"待验证"、"TBD"、"还不成熟"）
- 用Q&A形式整理常见疑问和解答
- 使用中文为主，技术术语保留英文（如Agent、Scrum、Prompt）

## Don'ts
- 不要只给抽象方案而没有具体示例
- 不要隐藏问题或不确定性
- 不要堆砌术语而不解释
- 不要忽略多人协作场景下的冲突和边界问题

## Examples
### Good Example
```
需求
教具越来越丰富，比如立方体教具，老师可能下发一个任务是：把顶点都点亮。此时学生操作每个顶点，可能发言也可能不发言，所以模型没有一个明确的提交时机。

现状
[描述当前状态]

期待
广义take turn含义：学生做了一系列的教具操作、发言or静音、物理动作及表情，由模型判定什么时候应该开始回应。

Level1: 足够感知信息
sensor(听觉、软件操作行为) → take turn decision

Level2: 更丰富的sensor
sensor(听觉、视觉、软件操作行为) → take turn decision
```

### Bad Example
```
本文将介绍一种先进的AI教学方法，该方法采用了最新的技术手段...
[空洞开场，没有明确问题]
```

## Keywords and Phrases
- "一句话描述"
- "核心点在于"
- "从效果上看"
- "从[X]角度看"
- "待验证"
- "边想边写"
- "好问题"
- "Level1/Level2/Level3"
- "Step1/Step2"

## 文章类型与风格

### 技术类 vs 管理类核心差异

| 维度 | 技术类 | 管理类 |
|------|--------|--------|
| **开篇** | 直接列"需求"或"目标" | 先描述组织"问题"和痛点 |
| **核心载体** | 代码块、JSON配置、流程图 | 人员表格、关系图、职责列表 |
| **层级结构** | Level1→2→3（能力递进） | 按角色/团队划分（横向分工） |
| **示例类型** | JSON结构、对话样本、状态描述 | Q&A形式的场景问答 |
| **不确定性** | "待验证"后简洁收尾 | "好问题"、"稍后补充"，持续迭代 |

---

### 技术类文章模板

**适用**: 技术方案、Agent设计、系统架构

**结构**:
```
1. 需求（具体场景描述）
2. 现状（已解决 + 暴露新问题）
3. 方案核心点（"一句话描述"）
4. 具体描述（含代码/配置/状态示例）
5. 效果或预期效果（或"待验证"）
```

**特点**:
- 用"一句话描述"概括核心
- 用类比解释抽象概念
- 状态变化用结构化表示（Old State → Action → Result State）
- 简洁收尾，不拖泥带水

**示例片段**:
```
方案核心点
一句话描述，SubAgent是在background运行的，而不断的将自己运行的结果作为
suggestion更新到MainAgent的信箱。MainAgent则每次携带最新suggestion来进行推理。
```

---

### 管理类文章模板

**适用**: 团队分工、流程规范、组织架构

**结构**:
```
1. 问题（组织痛点，一句话）
2. 解决思路（一句话）
3. 具体方案（人员/角色表格）
4. 各角色需求/职责（分层次：第一层、第二层、第三层）
5. 关系图（团队间协作流程）
6. Q&A（大量，预判各角色疑问）
```

**特点**:
- 开场可承认不成熟："以下想法还不成熟，边想边写"
- 对他人问题给予认可："好问题"、"是个好问题"
- 承诺后续补充："稍后再补充"、"这个再想一想"
- Q&A引用提问者姓名：`Q from @yunliao`

**示例片段**:
```
Q from @zhouyq: 具体执行的时候虚拟Team是Scrum会+站会？
A: 对，跑完整的Scrum流程

Q from @王栋: 板书及基础体验中是否覆盖了所有的体验类需求？
A: 初始设想里只包含了涉及策略的部分...这个再想一想，明确了再补充这个Answer。
```
