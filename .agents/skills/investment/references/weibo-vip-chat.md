# 微博 VIP 群文字发言续更

用于从微博聊天网页版中，按上次记录的断点继续收集指定群主的文字发言，并同步更新作者索引。

## 固定入口与对象

- 入口：`https://api.weibo.com/chat#/chat`
- 群聊：`正心以中修身以和客户服务`（页面可能显示为 `1正心以中修身以和客户服务群1`）
- 目标发言人：群主 `正心以中and修身以和`
- 原文文件：`investment/卢麒元/微博VIP群发言.md`
- 作者索引：`investment/卢麒元/卢麒元.md`

## 获取流程

1. 写入前先读原文文件顶部，以上一条已记录日期和内容作为续更断点。
2. 按项目约束使用 Chrome 浏览器控制打开入口；优先使用用户已有登录态和已打开的微博聊天页。
3. 进入目标群聊，确认消息发送者同时带有 `群主` 标记，避免误收群成员转述、引用或讨论。
4. 从最新消息向前回溯，直到与上次记录形成一屏以上重叠，确认跨过断点。
5. 只收录断点之后群主亲自发送的纯文字消息；保持原始顺序、措辞、标点和分段，不改写、不纠错。
6. 跳过语音、图片、表情、文件、升级/入群通知、系统提示、反应计数以及其他成员消息。文件名中的文字不算群主文字发言。
7. 页面把当天显示为时间、前一天显示为“昨天”时，使用当前北京时间换算为完整日期；日期不确定时不得猜测，应继续检查相邻日期分隔。

## 页面回溯要点

- 聊天内容可能位于 `.__panel` 滚动容器；普通 DOM 快照有时只显示搜索框和发送框。
- 可先读取页面可见文本确认当前日期和内容，再通过聊天面板滚动或 `PageDown`/`End` 回溯较长的语音段。
- 大量语音可能使单次滚动只前进几分钟。到达当前已加载记录边界后，继续触发一次滚动并检查日期是否发生变化。
- 不以“屏幕里没看到文字”为停止条件；必须到达上次断点或更早日期后才能结束回溯。

## 写入与索引

1. 在 `微博VIP群发言.md` 分隔线后、当前最新日期之前插入新日期章节，保持倒序排列：

   ```markdown
   ## YYYY-MM-DD

   第一条原文。

   第二条原文。
   ```

2. 不重复收录已经存在的句子；同一天再次续更时，追加到该日期章节末尾并保持聊天顺序。
3. 更新 `卢麒元.md` 的“关键观点速查”仅限新的分析框架、新指标，或与既有观点矛盾/显著升级的判断；重复验证、寒暄和操作口号不进入速查表。
4. 速查表内容是对原文的中性概括，出处写作 `微博 MM-DD`。
5. 完成后运行格式检查，并复读新增原文和索引条目，确认日期、发送者、文字范围及顺序无误。

## 完成汇报

说明新增日期与文字条数、更新了哪些索引观点，并明确哪些语音、文件或非群主消息因范围限制而未收录。
