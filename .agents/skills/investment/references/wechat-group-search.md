# 微信群聊搜索方法

用于从微信群「Satoshi Coffeehouse」和「禁言🤐」中按发言人提取 Medi（群昵称 `Mercator Moderatus`）或莎姐的历史发言，并从各群上次记录的截止时间继续更新。用户要求“更新莎姐和 Medi 发言”时，默认同时检查这两个群，除非用户明确限定群聊。

## 核心原则

聊天记录窗口顶部的普通搜索框搜索的是**消息正文**，不是发言人。直接搜索 `Mercator Moderatus` 只会找到正文中提到或 `@` 他的消息，不能代表这些消息由 Medi 发出。

正确方式是使用：

> 聊天记录 → 群成员 → 搜索成员昵称 → 选择成员

筛选成功后，聊天记录列表只显示该成员发送的内容。

## 手动操作步骤

1. 打开桌面微信，依次进入群聊「Satoshi Coffeehouse」和「禁言🤐」。每个群都完整执行以下步骤，不能因一个群没有新消息而跳过另一个群。
2. 点击聊天窗口顶部的「聊天记录」。
3. 如果窗口较小、右侧筛选项不可点击，使用 macOS 菜单栏：
   - `窗口 → 缩放（Zoom）`，或
   - `窗口 → 填充（Fill）`。
4. 点击「群成员」。
5. 在弹出的成员搜索框输入当前群昵称：
   - Medi：`Mercator Moderatus`
   - 莎姐：`中本莎`
6. 点击搜索结果中的成员。筛选标签出现「群成员」后，即表示发言人筛选已生效。
7. 列表默认按时间倒序显示：最新消息在上，向下滚动查看更早的消息。
8. 滚动到上次已记录的截止时间；只保留截止时间之后的新发言，并利用一屏重叠内容检查是否漏行。

## 稳定定位群聊与 Medi 私聊

当目标会话不在左侧可见列表时，使用主窗口左侧的会话搜索框。当前 macOS 微信版本存在一个自动化焦点陷阱：直接对搜索框调用 `setValue` 只改变显示值但不触发搜索；调用 `paste` 可能把文字错误写入当前聊天的消息输入框。因此必须使用真实键盘事件。

1. 重新读取微信主窗口，区分两个输入框：
   - 正确目标：左侧会话列表上方，辅助功能名称为 `Search`；
   - 禁止输入：右侧当前聊天输入框，带 `chat_input_field` ID 和当前会话名称。
2. 单击左侧 `Search`，重新读取界面，并确认焦点仍显示为 `Search`。
3. 使用真实键盘输入（`typeText`），不要使用 `setValue` 或 `paste`：
   - 「禁言🤐」：输入拼音 `jinyan`；
   - Medi 私聊：输入 `Medi`（也可用 `Mercator`）；
   - 「Satoshi Coffeehouse」：输入 `Satoshi`。
4. 输入后确认搜索框出现对应的 `Value`，再按回车打开首个结果。
5. 重新读取界面，以 `current_chat_name_label` 验证打开的会话必须精确等于目标名称；不能仅凭搜索词或会话摘要判断。
6. 如果文字误入右侧聊天输入框，立即用 `setValue(chat_input_field, "")` 清空，确认「发送」按钮恢复禁用；绝不能按回车或点击发送。
7. 切换下一个会话前，点击搜索框的「Clear」按钮或确认搜索框已清空，再重新执行以上步骤。

已验证的定位词：`jinyan` 可打开「禁言🤐」，`Medi` 可打开 `Mercator Moderatus` 私聊。该方法不依赖目标会话是否近期活跃、是否置顶或是否保存到通讯录。

## 日期换算

微信聊天记录可能不显示完整日期，而显示相对日期。整理时必须根据提取当天的日期换算：

| 微信显示 | 处理方式 |
|---|---|
| `今天`或仅显示时间 | 使用提取当天日期 |
| `昨天` | 提取日期减一天 |
| `星期一`至`星期日` | 映射到当前日期之前最近的对应星期 |
| `2026-8-21 21:47` | 直接使用完整日期时间 |

跨日提取时，应在原文文件中按日期分节，不要把相对日期原样写入长期资料。

## 断点续更

更新前先读取最近一份 `source.md` 的末尾，并按群聊分别确认：

- 最后记录日期；
- 最后记录时间；
- 最后一条消息正文。

两个群的截止时间必须独立维护。同一发言人在不同群的最后消息时间可能不同，不能用「Satoshi Coffeehouse」的断点跳过「禁言🤐」消息，反之亦然。若历史文件尚未记录来源群或某群没有既有断点，应在该群内向前检查至最近一次已覆盖日期，并在新文件中明确说明首次补录的起点。

随后在微信群成员筛选结果中向下滚动，直到看到这条已记录消息。新记录从它的下一条开始。若上次截止消息之后同一分钟还有其他消息，应比较正文，不能只按分钟去重。

每次翻页保留前后屏幕的重叠消息，以正文和时间共同去重，避免滚动跨度造成遗漏。

## 原始记录规范

- 莎姐的发言只保留投资相关部分：行情、市场结构、流动性、进出场、仓位、风控和交易方法论；吃饭、段子、收费、群务及一般社交闲聊不入库。
- 每条记录必须能识别来源群。若同一份 `source.md` 同时收录两个群，应按“日期 → 群名 → 发言人”分节；同文消息分别出现在两个群时保留一次，并注明同时发布的群聊。
- 保留英文原始拼写、大小写和语法错误，不在 `source.md` 中润色。
- 保留 `@成员`、具体价位和仓位比例。
- 图片、引用消息或问答上下文不能从无障碍文本完整恢复时，要明确标注缺失，不自行补写。
- 微信导出文本中出现异常字符（例如句中孤立的 `?`）时原样保留，并在文件头说明。
- 中文翻译写入 `source-zh.md`；解释性修正只放在翻译或 `notes.md`，不能改动英文原文。

## 自动化操作注意事项

- 每次点击、滚动或切换窗口后，重新读取当前界面，不能复用旧的元素编号。
- 「群成员」有时因窗口尺寸被判定为屏幕外；先最大化聊天记录窗口再操作。
- 聊天记录工具栏可能有一个无标题按钮；若点击「群成员」没有反应，可先展开工具栏，再重新读取界面并点击当前的「群成员」。
- 微信可能在打开或筛选聊天记录时提示“为了账号安全，请重新登录”。完成二维码登录后，应重新进入群聊并从头执行成员筛选。
- 成员筛选完成后，需用对应群聊会话列表中的最新发送人进行一次交叉检查；例如会话摘要显示 `Mercator Moderatus: ...`。
- 会话搜索必须优先采用上文的“真实键盘输入 + 回车 + `current_chat_name_label` 验证”流程。若只看到搜索框值变化、会话列表却没有响应，说明使用了不会触发搜索的赋值方式，应清空后改用 `typeText`。

## 入库流程

提取完成后按以下顺序处理：

1. 保存英文原文为新内容目录下的 `source.md`。
2. 非中文内容生成完整翻译 `source-zh.md`。
3. 生成结构化精读笔记 `notes.md`。
4. 更新 [`Medi_and_莎姐.md`](../../../../investment/Medi_and_莎姐/Medi_and_莎姐.md) 的对话记录入口。
5. 仅在出现新分析框架、指标或显著观点变化时更新“关键观点速查”。
6. 在 `sources/sources.jsonl` 追加来源记录；JSONL 只追加，不删除或重写旧记录。

入库前再次确认「Satoshi Coffeehouse」和「禁言🤐」均已检查，并在 `source.md` 文件头写明本次实际覆盖的群聊及各自断点；若某群因登录、权限或记录缺失未能检查，必须明确标注为未完成，不能把另一群的完成状态当作整体完成。
