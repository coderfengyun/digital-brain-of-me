# 洪灏微博研报获取

用于获取洪灏最新或指定的微博图文研报，并按用户要求完成下载、图片 OCR、结构化笔记与索引注册。

## 固定入口与选帖

- 洪灏微博主页：`https://weibo.com/u/7799274131`
- 按项目约束使用 Chrome 浏览器控制，不使用外部网页抓取替代微博页面。
- 在作者主页的“微博”标签中找目标帖，不要在“文章”标签中查找。
- 用户给出标题或关键词时据此定位；未指定时，从最新帖子中选择长文分析类研报，跳过转发、活动消息和短评。
- 进入帖子后先展开全文，记录原始链接、发布日期、标题、正文与图片顺序。

## Phase 1：保存正文与配图

1. 创建 `investment/洪灏/YYYYMMDD-文章简短标题/`。同一天多篇按作者内容目录规则追加字母。
2. 微博图片带签名认证，外部 `curl` 通常无法取得原图。必须在浏览器中打开配图和“查看大图”，让页面加载 `mw2000` 分辨率资源。
3. 从浏览器已加载的图片资源或网络响应中保存每张 `mw2000` 图片，按原帖顺序命名为 `image_1.jpg`、`image_2.jpg` 等。若当前浏览器控制接口不提供网络响应导出，应使用它支持的页面资源导出能力；不得以低清截图冒充原图。
4. 写入同目录 `article.md`，包括：
   - 元信息 blockquote：作者、来源、发布日期、原帖链接；
   - 微博正文；
   - 按原帖顺序排列的本地配图引用。
5. 复核图片数量、顺序和分辨率，确认正文已完整展开。

## Phase 2：OCR 图片文字

1. 对包含正文、表格说明或注释的每张图片使用 `ocr` skill；纯装饰图片或只需视觉解读的图表可以不做 OCR。
2. 输出命名为 `image_N_OCR.md`，与原图同目录。
3. 人工对照原图校对专有名词、数字、百分比、单位、图例、断行和乱码。不得把未经核对的 OCR 结果直接视为研报原文。
4. 按图片顺序将校对后的文字并入 `article.md` 或明确链接，形成可连续阅读的完整来源文本。

## Phase 3：结构化笔记与注册

除非用户明确只要求下载，否则执行完整处理：

1. 使用 `paper-reading` skill 阅读合成后的完整来源文本；洪灏研报通常选择 Narrative 模板。
2. 分配 `paper-YYYYMMDD-XXX` ID，并在同目录生成 `notes.md`。
3. 追加注册到 `sources/sources.jsonl`，一行一个 JSON 对象，`output` 指向该研报的 `notes.md`。
4. 更新 `investment/洪灏/洪灏.md`，添加原文和笔记链接。
5. 仅当内容提供新的分析框架、新指标，或对既有观点作出矛盾/显著升级的判断时，更新“关键观点速查”；重复验证和应用实例不追加。

## 范围与停止条件

- 用户明确“只下载”时执行到 Phase 1；若同时要求转录图片，则执行到 Phase 2。
- 图片无文字时可跳过 OCR，但需在完成汇报中说明。
- 页面要求登录时保留当前页面并请用户在选定浏览器中完成登录；不要改用搜索引擎或其他来源绕过登录。
- 无法取得原图、正文未展开或日期无法确认时，不得把任务报告为完整完成。

## 完成检查

- 目录名、发布日期、原帖链接正确。
- 正文、图片及 OCR 均按原帖顺序保存，没有漏图或重复图。
- `article.md`、`notes.md`、作者索引与 `sources.jsonl` 互相指向正确。
- 汇报实际完成的 Phase、生成文件及任何跳过项。
