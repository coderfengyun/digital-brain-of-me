### 叙事结构

```
前提: AI不只是提升生产力，而是改变公司的构建方式
↓
视角转换: 从"哪些流程加AI" → "如果从零开始，哪些工作不该经由人力"
↓
组织模型: 传统公司 = 开环系统（信息损耗大）
          AI-native公司 = 闭环系统（结构化记录→智能层→自我调节）
↓
操作原则: 让组织"可被查询"（queryable）
├→ 具体做法: 录会议、减少私聊、全面嵌入Agent
└→ 目标状态: 智慧中枢——即时回答"公司到底发生了什么"
↓
角色重塑: 员工 = 意图表达者；管理者 = 围栏设计者
↓
结论: 早期创业公司有先发优势，应从Day 1按此方式搭建
```

### 核心论点一：操作系统视角取代生产力视角

Diana的核心判断：大多数人仍用"效率提升"框架看AI——工程师写代码更快、客服更自动化。但真正的变化是结构性的。

关键金句：「一个真正会用AI工具的人，今天已经能做出过去需要一整支团队才能完成的功能。」

因此正确的问题不是"公司哪些流程可以加上AI"，而是"如果今天从零开始建立公司，哪些工作原本就不该经由人力层层处理"。

AI-native公司的正确顺序：不是先画组织架构图再塞AI，而是从Day 1把公司设计成可被AI理解、查询、分析与自我改善的系统。每个重要行动都产生可被AI读取的artifact。

**核心隐喻**：创始人应该画「信息流图」而不是「组织架构图」。

### 核心论点二：开环→闭环的组织模型

借用控制论概念：
- **开环系统**（传统公司）：决策→执行→结果，但反馈依赖人工复盘，信息损耗大
- **闭环系统**（AI-native公司）：每次会议/工单/客户反馈/产品决策/销售通话/工程交付 → 结构化记录 → 回馈智能层 → 自我调节

### 核心论点三：让组织"可被查询"

第一步操作建议：
1. 录下重要会议，AI自动生成摘要
2. 减少藏在DM和邮件中的信息
3. 在 Slack、Linear、GitHub、Notion、客服工具、销售电话与运营数据中全面嵌入AI Agent

目标：打造一个能即时回答"现在公司到底发生了什么"的智慧中枢。

### 支撑：管理流程重构示例

一个Agent读取 Linear工单 + Slack工程频道 + GitHub + 客户邮件 + 客服工具 + Notion高阶计划 + 销售通话 + 站会记录 → 不仅整理会议摘要，还能分析上轮迭代交付了什么、是否满足客户需求、哪些功能无效 → 为工程师提供更可预测的迭代计划。

Diana透露：多家YC公司已有类似实践，工程迭代周期缩短一半，产出接近10倍。

### 支撑：员工角色重塑

- **员工新核心能力**：精准描述意图，用自然语言向AI交代目标，持续教会AI更高效完成工作
- **管理者新核心任务**：设计"运行围栏"——定义目标、边界条件、异常处理机制，校准系统与战略对齐
- **危险信号**：如果一个人花大量时间在"整理信息"和"传话"上，岗位价值正在被侵蚀

## 批判性思考

### 1. 这个论点的前提假设是什么？如果假设不成立会怎样？

**核心假设**：公司的关键信息可以被完整、准确地结构化记录。

如果不成立：很多关键决策信息是隐性的（判断力、直觉、政治博弈、人际信任），这些难以被结构化。如果AI只能读取"显性信息流"，闭环系统可能产生"垃圾进垃圾出"的精确但错误的决策。

### 2. 作者回避了什么问题？

- **权力与政治**：组织不仅是信息处理系统，也是权力分配系统。让所有信息透明化会遭到既得利益者的抵制。
- **信息质量**：从Slack、会议录音中提取的信息噪声极大，如何区分信号和噪声？
- **安全与隐私**：让一个AI读取公司全部信息流，本身就是巨大的安全风险和合规挑战。
- **规模边界**：10人公司和1000人公司的信息复杂度完全不同，这套方案在什么规模会失效？

### 3. 这对我/我们的工作有什么启发？

与 digital-brain 项目的深度共鸣：
- 「让组织可被查询」= digital-brain 的核心设计哲学——让个人知识系统对AI可读
- 「信息流图 > 组织架构图」= CLAUDE.md 的 Module Navigation 路由表设计
- 「每个行动产生artifact」= append-only JSONL + 结构化 schema 的设计选择
- 「闭环系统」= sources pipeline（输入→处理→输出→可被再次查询）

**关键差异**：Diana 讨论的是多人组织，digital-brain 是个人系统。个人系统不存在信息搬运和政治问题，但「让自己的所有思考对AI可读」这个原则完全适用。

## 关键洞察

- AI-native的本质不是"用AI提升效率"，而是从Day 1把公司设计为一个对AI可读、可查询、可自我改善的闭环系统
- 创始人应该画信息流图（数据从哪来→流向哪个AI→输出什么结论→反馈到哪个决策节点），而不是组织架构图
- "可被查询"(queryable)是AI-native组织的第一性原则——让AI能即时回答"现在公司到底发生了什么"
