# On-Policy Distillation（在策略蒸馏）

**作者**：Kevin Lu，与 Thinking Machines Lab 的同事合作  
**发布日期**：2025-10-27  
**原文**：https://thinkingmachines.ai/blog/on-policy-distillation/

## 引言

LLM 在聚焦领域能够达到专家级表现，这来自多种能力的叠加：感知输入、检索知识、选择计划与可靠执行。相应的训练大体分为三阶段：预训练赋予语言、广泛推理和世界知识等通用能力；中期训练注入代码、医学数据库或公司内部文档等领域知识；后训练则诱导指令遵循、数学推理或对话等目标行为。

训练充分的小模型常能在专长领域胜过更大的通用模型。小模型可在本地部署，便于隐私与安全控制，也更容易持续更新，并能降低推理成本。要获得这些优势，必须选对后训练方法。学生模型的后训练可分为两类：

- **在策略训练**：从学生模型自身采样轨迹，再为轨迹赋予奖励。
- **离策略训练**：学生模仿某个外部来源提供的目标输出。

以训练紧凑模型解数学题为例，强化学习从学生自身采样答案，再由人或可靠教师模型判断是否正确。它的优点是学生直接针对自己的错误学习；缺点是反馈稀疏——无论轨迹有多少 token，一次训练回合只提供固定数量的信息。学生可能只知道“21”是错的，却不知道错在运算顺序还是算术步骤。

离策略训练通常采用监督微调（SFT），训练材料可以来自高性能教师。蒸馏让学生匹配教师的输出分布，既可使用教师每一步的完整 next-token 分布（logit distillation），也可使用采样序列；后者是教师分布的无偏估计，目标相同。离策略蒸馏已被用于指令遵循、数学与科学推理、临床信息抽取和多轮聊天。

但离策略学习发生在教师常访问的状态，而不是学生真正会到达的状态。学生一旦犯了教师不会犯的早期错误，就会进入训练中未见过的上下文，误差沿长序列累积。它还可能只学会教师的风格与自信，而未得到事实准确性。

类比下棋：在策略 RL 像自己下棋，终局输赢与自己的行动相关，却不能指出哪一步有问题；离策略蒸馏像观看大师棋局，能看到强招，却是在新手很少到达的盘面上。我们想要的是教师对学生自己的每一步从“漏着”到“妙着”逐一评分——这就是在策略蒸馏。

## 在策略蒸馏：两全其美

核心做法是：从**学生模型**采样轨迹，再由高性能教师对轨迹中的**每个 token**评分。这样既保留在策略训练对学生真实状态的相关性，又获得蒸馏的稠密监督。

| 方法 | 采样 | 奖励信号 |
|---|---|---|
| 监督微调 | 离策略 | 稠密 |
| 强化学习 | 在策略 | 稀疏 |
| 在策略蒸馏 | 在策略 | 稠密 |

这一思路受到 DAGGER 的启发：它把学生访问状态上的教师评价纳入迭代 SFT；它也与过程奖励模型相似，后者对思维链的每一步评分。本文延伸了已有的在策略蒸馏工作，并借助 Tinker API 复现 Qwen3 的结果：在推理基准上，在策略蒸馏用远低于 RL 的成本达到相当表现。

## 实现

### 损失函数：反向 KL

本文采用逐 token 的反向 KL，即在相同历史轨迹条件下，学生分布与教师分布的差异：

`KL(πθ || πteacher) = Ex~πθ[log πθ(x[t+1]|x[1..t]) - log πteacher(x[t+1]|x[1..t])]`

最小化反向 KL 会让学生在自己实际到达的每个状态中逼近教师。两者行为一致时，KL 为零。实验使用折扣因子 0：每个时间步只优化紧邻的下一个 token，不考虑更远 token；作者称更大的折扣因子在实践中没有改善。

反向 KL 与 RL 有天然协同性，因为 RL 通常也在优化由奖励模型诱导的序列级反向 KL。但这里的反向 KL较难被“奖励黑客”利用：低 KL 就意味着教师认为该行为概率高。它还具有 mode-seeking 特性，会集中学习教师的特定行为，而不是把概率摊在多个次优选项上，并能减轻 exposure bias。

这种方法节省计算：不必等整条轨迹生成完毕才计算奖励，因此可用短轨迹或部分轨迹；查询教师 log-prob 只需一次前向传播；轨迹由更小、更便宜的学生生成；也无需额外奖励模型或标注模型。未来可考虑把逐 token 蒸馏奖励与序列级环境奖励结合。

### 示例

在 SimpleBench 的例子中，学生 Qwen3-4B-Instruct-2507 把一道涉及“冰块放入煎锅”的题误当作纯数学题，忽视冰会融化，正确答案应为 “B. 0”。教师 Qwen3-235B-A22B-Instruct-2507 对把学生引入歧途的短语起始 token 给出较高反向 KL 惩罚，这些 token 直观上正是决定推理分叉的 “forking tokens”。最终错误答案反而没有被重罚，因为在前面错误轨迹给定后，它已完全可预测。

### 伪代码与步骤

1. 初始化教师客户端；教师只需返回 log-prob，不需反向传播。
2. 像 RL 一样从学生采样轨迹，并保存学生的 log-prob。
3. 把同一批学生轨迹交给教师计算 log-prob，两者之差即反向 KL。
4. 令逐 token advantage 等于负的反向 KL，再调用 RL 的 importance-sampling loss 更新学生。

换言之，如果现有 RL 实现已有 KL 正则项，核心变化近似只是把正则模型换成教师模型。

实验通常先用中期训练使学生具备领域知识，让教师行为至少落在学生分布的支持集内，然后再用在策略蒸馏做后训练。若学生生成相关 token 的概率为零，反向 KL 的 mode-seeking 本身无法创造新的支持，因此不能替代知识注入阶段。

## 用蒸馏训练推理

作者用 Qwen3-32B 教师训练 Qwen3-8B-Base 学数学推理（文后更新称模型后来从 Tinker 下线，配方已改为 Qwen3.5-9B-Base 与 Qwen3.5-9B）。

### 离策略蒸馏基线

所有实验先进行离策略蒸馏式的中期训练：在 OpenThoughts-3 中由 QwQ-32B 生成的推理样本上做 SFT。对 Qwen3-8B-Base 用 40 万提示全参数微调，AIME’24 达 60%。性能随数据量近似对数线性增长：前 5–10 万提示收益便宜，后续提升越来越贵。以 40 万样本检查点为起点，若继续离策略蒸馏并外推趋势，要到约 200 万提示才可能从 60% 升到 70%，且这个外推假设曲线不会提前停滞。

### 强化学习基线

Qwen3 技术报告在类似 SFT 初始化上用 17,920 GPU 小时的 RL 得到 AIME’24 67.6%、GPQA-Diamond 61.3%。报告中的在策略蒸馏只用约 1,800 GPU 小时就达到 AIME’24 74.4%、GPQA-Diamond 63.3%，即约十分之一成本。

### 在策略蒸馏结果

从 SFT-400K 检查点出发，在策略蒸馏约 150 步就让 AIME’24 达到 70%；150 步约对应 7.7 万个提示，每个提示采 4 条轨迹。它也显著缩小 LoRA 与全参数微调的差距：rank 32 LoRA 在 SFT 后落后 13 个百分点，在在策略蒸馏后只落后 6 个百分点。

跨方法比较成本并不简单，因为训练、采样、log-prob 计算的硬件利用率不同。作者用 FLOPs 估算，这会高估容易在 GPU 上并行的 log-prob 计算成本。若现成 SFT 数据集的生成成本已摊销，在策略蒸馏相对外推到 200 万样本的 SFT 基线约节省 9 倍 FLOPs；按实际 GPU 小时可能接近 18 倍。若新任务没有离策略数据集，还要把教师生成 SFT 数据的成本计入，估算节省约 30 倍。

## 用蒸馏做个性化

另一个用途是把特定语气、输出格式、工具使用或成本预算等行为，与新领域知识结合。单次轻量微调往往做不到这一点；前沿实验室可以依靠复杂后训练栈、专有数据和奖励模型，但普通实践者成本很高。作者用一个学过公司内部文档的助手来展示替代路径，并把它与持续学习或测试时训练联系起来。

### 训练内部助手

目标有两个：一是掌握公司内部文档知识，用 internal QA 衡量；二是保留强指令遵循能力，用 IF-eval 衡量。

作者从已做过后训练的 Qwen3-8B 开始。为减轻中期训练造成的灾难性遗忘，他们用 Tulu3 提示让 Qwen3-8B 重新采样聊天数据，把这种在策略背景数据作为前向 KL 正则。用 Qwen3-8B 自身采样比用 Qwen3-32B 更能保留原有聊天能力，说明数据来源十分敏感。

随后在内部文档与聊天数据的不同比例上微调。文档比例提高会改善知识，但即使至少混入 30% 聊天数据，也无法保持原始 IF-eval；事实上，哪怕数据 100% 是聊天，实践学习率下也会退化。LoRA 虽限制参数更新，仍不能保住 IF-eval，而且学到的新知识更少。

### 在策略蒸馏恢复后训练行为

作者先以 70% 内部文档、30% 聊天数据完成中期训练，再把较早版本 Qwen3-8B 作为教师，在 Tulu3 提示上做在策略蒸馏，只负责恢复指令遵循，不再接触内部文档。结果如下：

| 模型 | Internal QA | IF-eval |
|---|---:|---:|
| Qwen3-8B | 18% | 85% |
| + 100% 文档中期训练 | 43% | 45% |
| + 70% 文档中期训练 | 36% | 79% |
| + 70% 文档中期训练 + 蒸馏 | 41% | 83% |

也就是说，蒸馏几乎恢复全部指令遵循，同时没有牺牲新知识，甚至出现少量正迁移。可以把语言模型本身视为奖励模型：教师的高概率行为得到奖励。任何可访问 `compute_logprobs` 的开放权重指令模型都能以这种方式充当教师。更一般地，可以交替进行“学习新知识”和“恢复原有行为”两个阶段，以支持持续学习。

## 讨论

### 稠密监督大幅提高计算效率

RL 与在策略蒸馏都通过反向 KL 剪枝基础策略的行动空间，差异在反馈密度。RL 每个 episode 只教 `O(1)` bits；蒸馏则随 token 数增长到 `O(N)` bits。

作者从同一个 Qwen3-8B-Base 初始化出发：先在 DeepMath 上用 rank 128 LoRA 做 RL，所得模型作为教师；再把教师策略蒸馏回原始 base。蒸馏用约 7–10 倍更少的梯度步恢复教师表现，对应累计计算效率提高约 50–100 倍。RL 需约 70 步，蒸馏不到 10 步便让反向 KL 接近 0 并恢复 AIME 分数。

原因包括：RL 通常必须用接近评测长度的上下文，才能学会在长度限制前完成并避免格式惩罚；蒸馏没有“完成/未完成”的奖励断崖，可用短上下文。若 SFT 初始化足够强、教师策略处在学生支持集内，稠密反馈还能用更小 batch 并降低梯度噪声。若支持条件不满足，就仍需大 batch。

### 蒸馏能更有效复用提示数据

RL 在同一提示上训练多轮常会记住最终答案。蒸馏拟合教师完整分布，而不是单一答案，因此能在同一提示上采许多不同轨迹。作者只随机选一个极限题提示，连续训练 20 步，每步 256 条 rollout，总共 5,120 条被评分序列，最终大致匹配教师的 AIME’24 表现。它不一定计算效率高，但表明提示数据极少时仍可复用。

### RL 在语义策略空间里搜索

在策略蒸馏能用很少更新复刻 RL 的成果，说明 RL 的主要成本也许不在梯度更新，而在**搜索**：采样策略并分配信用。预训练的 SGD 在高维参数空间中探索，所需信息巨大且很难蒸馏；RL 更像在语义策略空间探索。基础模型必须先有非零成功率，RL 才能通过偶然采样发现并强化更好的策略。一旦好策略被找到，蒸馏就可跳过 RL 的中间课程，直接学习最终策略。

类比科研：发现答案需要大量探索，但发现后可以用自然语言快速教给别人；与之相反，运动等直觉身体技能存在于个体内部语言中，较难直接传授，只能反复练习。

### 在策略学习用于持续学习

持续学习要获得新知识，又不损伤旧能力。RL 忘得较少，但擅长塑造行为，不擅长教授新知识；SFT 能教知识，却会破坏行为。

作者进一步从 Qwen3-32B 以温度 1.0 采样其自身在 Tulu3 提示上的输出。理论上数据对原模型的期望 KL 为 0，但用任何实际的非零学习率做 SFT 都会降低 IF-eval。可能原因是有限 batch 的经验分布总与真实分布略有不同，每次非零更新都会让当前模型偏离原策略；随后旧样本相对新模型逐渐变成离策略数据，误差在长序列中累积。在策略蒸馏则始终从当前学生采样，固定教师提供收敛目标，因此自蒸馏不会像 SFT 那样持续退化。

## 结论

本文把在策略蒸馏用于数学推理和持续学习助手，并与离策略蒸馏、在策略 RL 比较。它结合了在策略训练的可靠性和稠密奖励的成本效率：学生从自己会访问的状态采样，教师逐 token 监督，从而以远低于高计算 RL 的成本得到目标能力。

作者强调，实验只采用了简单、直接的实例来凸显优势。后续方向包括新的蒸馏应用、更好的教师监督、数据效率，以及持续学习。实现已发布在 Tinker cookbook。
