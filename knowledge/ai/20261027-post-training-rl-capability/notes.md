## 🗺️ 全局地图

### 一句话摘要

> Post-training 的关键不再是单选 SFT、RL 或蒸馏，而是用多维指标判断一个模型是否仍有可探索的能力分布，并区分 RL 把已有正确轨迹推向高概率与真正扩大可泛化能力边界这两种效果。

### 结构地图

```text
问题：RL 的分数提升到底来自新能力，还是已有能力重排？
↓
共同背景：SFT、RL、蒸馏已组成反馈循环
├─ SFT：建立最低任务/协议能力，同时保留探索空间
├─ RL：在环境中提高高奖励轨迹概率
└─ 蒸馏：把强教师和多条成功路径压入部署模型
↓
争议一：什么是好的 RL 起点？
├─ 只看 SFT pass@1 → 容易选中被简单/同质数据“优化过”的 checkpoint
└─ 同看 held-out loss、pass@k、entropy、format/tool pass rate → 衡量潜力
↓
争议二：RLVR 是否创造新能力？
├─ pass@k 视角：base 大量采样可找回轨迹 → 更像能力唤醒/概率重排
├─ CoT-Pass@k 视角：过程正确性提高 → 可能有真实推理改进
└─ 受控迁移视角：base 高预算仍为 0、RL 后成功并迁移 → 更像能力扩展
↓
工程结论：不用单一指标定义能力；必须同时观察覆盖面、过程正确性和迁移
```

## 📖 领域全景

### 发展脉络

```text
阶段 1：线性 post-training
预训练 → SFT → RLHF/RLVR → 安全与评测
↓
阶段 2：生成—筛选—回灌
Rejection Sampling / ReST / STaR 把成功轨迹重新固化进模型
↓
阶段 3：reasoning model 多阶段训练
冷启动、reasoning RL、rejection sampling、通用 RL、蒸馏交替出现
↓
当前争论：优化部署表现，还是扩大能力边界
pass@1、pass@k、CoT-Pass@k、分布外迁移分别测量不同对象
```

文章最有价值的地方，不是为“RL 是否创造能力”给出答案，而是把这个看似二元的问题拆成三个可测量对象：

1. **部署可用性**：一次采样能否答对，即 pass@1。
2. **可达覆盖面**：给定采样预算后，模型能解决多少不同问题，即 pass@k。
3. **正确且可迁移的策略**：推理路径是否正确，并能否迁移到新任务或更难环境。

三者可能同时向不同方向变化。RL 完全可能让 pass@1 上升、pass@k 下降，同时让某些任务的正确 CoT 比例上升。因此，“能力”若不先给出操作性定义，争论就会把不同实验结果误判为互相否定。

## 🗂️ 方法分类

| 类别 | 代表工作 | 核心思路 | 优势 | 局限 |
|------|----------|----------|------|------|
| 多阶段 post-training | Qwen3、DeepSeek-R1 | 冷启动/SFT、RL、rejection sampling、通用训练循环组合 | 同时兼顾格式、推理和通用能力 | recipe 多变量耦合，难归因单一阶段的贡献 |
| 预测 RL 潜力 | *Quagmires in SFT-RL Post-Training* | 用 held-out generalization loss 和大 k pass@k 替代只看 SFT 分数 | 有助于在昂贵 RL 前筛选 checkpoint | 主要证据来自不超过 12B 的模型和数学 benchmark |
| 能力唤醒解释 | *Does Reinforcement Learning Really Incentivize Reasoning Capacity…* | 用大 k pass@k 估计 base model 的潜在可达边界 | 揭示 pass@1 改善可能只是概率重排 | 有限 k 不能证明某条路径在分布中绝对不存在；最终答案可能是猜对的 |
| 正确推理解释 | *RLVR Implicitly Incentivizes Correct Reasoning…* | CoT-Pass@k 同时要求推理链和答案正确 | 把过程质量纳入能力定义 | 依赖第二个 CoT verifier，其误差会进入指标 |
| 受控边界扩展 | Ariadne 视觉迷宫 | 精确控制路径长度/转弯数，测试 base 0% 区域及真实导航迁移 | 难度可控，并有 OOD 迁移证据 | 视觉迷宫是窄任务，不能直接外推到通用语言推理 |
| competence 门槛 | 因果图推理 RLVR | 比较不同模型规模与因果查询层级上的 RLVR/SFT 泛化 | 解释为何相同 RL recipe 对不同 base 差异很大 | 结论依赖因果图任务和 Qwen2.5 系列 |
| 教师蒸馏 | DeepSeek-R1 distilled models 等 | 把教师知识与成功轨迹注入较小模型 | 学生无需独立探索罕见高质量状态 | 教师偏差被一并压入；“蒸馏总优于 RL”缺乏普遍对照实验 |

## 🔬 核心证据表

| 论点 | 创新点 | 支撑数据 | 数据来源 | 说服力评估 |
|------|--------|----------|----------|------------|
| 高 SFT 分数不能可靠预测 RL 结果 | 把 checkpoint 选择从当前分数转向潜力预测 | 数百个模型、最高 12B、7 个数学 benchmark、最多 256 次重复、超过 100 万 GPU 小时；generalization loss 与 pass@large-k 的预测指标最高改善约 0.5（约 2 倍） | [Kang et al., 2026](https://arxiv.org/abs/2510.01624) | **高（范围内）**：实验规模大，但任务集中于数学推理、GRPO 和特定模型族 |
| RLVR 主要重排已有推理轨迹 | 用大 k pass@k 近似潜在能力边界 | 小 k 时 RL 模型领先；大 k 时 base 可接近或超过 RL；RL 生成路径可在 base 分布中采到 | [Yue et al., 2025](https://arxiv.org/abs/2504.13837) | **中高**：跨模型/任务现象稳定，但结论取决于 pass@k 是否足以代表“能力” |
| RLVR 能提升正确推理而非只提高答案命中率 | CoT-Pass@k 要求答案和中间推理同时正确 | 在该指标下，RLVR 模型在所有测试 k 上表现出正确推理泛化提升 | [Wen et al., 2026](https://arxiv.org/abs/2506.14245) | **中**：修正了指标盲点，但 CoT 正确性验证自身需要可靠评审器，也未直接证明产生了 base 支持集之外的轨迹 |
| RLVR 在受控任务中可能扩大可达边界 | 用可控视觉迷宫和 OOD 导航测试“base 高预算仍为 0”区域 | RLVR 成功解决 base 在增加 pass@k 后仍为 0% 的迷宫，并零样本提升 MapBench、ReasonMap | [Shen et al., ACL 2026](https://aclanthology.org/2026.acl-long.2102/) | **中高（窄域）**：有受控难度和真实任务迁移，但只证明特定视觉空间推理场景 |
| RLVR 泛化需要足够 base competence | 把模型规模和因果查询层级作为能力门槛变量 | 在 3B–32B Qwen2.5 模型上，RLVR 只在特定规模/训练层级组合中优于 SFT；足够初始能力时才改善边缘化策略与中间概率计算 | [*Generalization of RLVR Using Causal Reasoning as a Testbed*](https://arxiv.org/abs/2512.20760), ICLR 2026 | **中高（窄域）**：支持“有种子能力才能放大”，但对开放式 agent/工具任务的适用性未知 |
| 小模型通常蒸馏优于直接 RL | 用教师直接提供学生难以探索的状态 | **例子**：DeepSeek-R1 发布了基于 Qwen/Llama 的 1.5B–70B 蒸馏模型；能力边界研究也观察到蒸馏可注入新知识 | [DeepSeek-R1](https://arxiv.org/abs/2501.12948)、[Yue et al., 2025](https://arxiv.org/abs/2504.13837) | **中低（一般化表述）**：方向合理，但文章没有提供“同预算、同学生、蒸馏 vs RL”的系统对照，不能推出普遍优越性 |

### 证据核验后的结论

文章对各篇论文主结论的概括基本准确，但“2026 年的共同答案”更像工程综合判断，而不是由单个统一实验直接证明的共识。特别是：

- 大 k pass@k 论文回答的是“有限采样预算下能否在 base 中找到成功答案”。
- CoT-Pass@k 论文回答的是“成功答案是否来自正确推理过程”。
- Ariadne 回答的是“受控空间任务中，RL 后是否进入 base 在给定预算内不可达的区域”。

它们操作化的“能力边界”不同，结果可以同时成立。

## 🤔 批判性思考

| 问题 | 分析 |
|------|------|
| 核心假设及失效场景 | **假设 1**：大 k pass@k 足以近似 base 的能力支持集。若正确答案可被猜中、采样温度不合适或稀有轨迹概率低于有限预算，指标会误判。 **假设 2**：CoT verifier 能可靠判断推理过程。若评审器偏好特定书写风格、漏掉隐含错误，CoT-Pass@k 也会失真。 **假设 3**：受控 benchmark 的能力增长可以迁移到复杂生产环境；在开放工具调用、长期交互和非平稳环境中可能失效。 |
| 关键局限 | 文章把不同模型规模、任务模态、RL recipe 和评测预算下的研究放进同一叙事，便于理解但弱化了可比性；没有给出脚注完整书目信息和关键 effect size；“小模型蒸馏优于直接 RL”更多是合理工程推断，不是已被系统证明的普遍规律；“SFT、RL、蒸馏合并成循环”描述了领先 recipe，却没有证明这是成本最优或所有任务都需要的结构。 |
| 实验充分性 | **已验证**：数学任务上的 SFT checkpoint 预测、大 k 能力覆盖、CoT 正确性、视觉迷宫边界扩展、因果推理 competence 门槛。 **未统一控制**：base model、训练 token/compute、rollout 数、采样温度、verifier、k 值和 held-out 难度。 **尚未充分测试**：真实 agent 工具链、长期任务、非可验证奖励、模型规模扩展后这些规律是否仍成立。 |

### 最关键的概念澄清

“RL 是否创造新能力”不是一个在不定义预算和评测标准时就能回答的问题。更严格的说法应是：

> 在指定 base model、采样策略、推理预算、verifier 和任务分布下，RL 是否提高了正确策略的可达性、过程可靠性与分布外迁移。

这一定义避免把“理论上概率非零”误当成“工程上已具备能力”，也避免把 pass@1 的可用性提升直接升级为能力扩展。

## 🔮 开放问题与趋势

1. **统一能力指标**：需要同时报告 pass@1、pass@k、正确轨迹多样性、CoT/过程正确性和 OOD transfer，而不是争夺唯一指标。
2. **训练预算公平比较**：蒸馏、SFT 和 RL 应在相同学生模型、数据可见性和总 compute 下比较，否则“谁决定上限”没有可比答案。
3. **边界 prompt 的保护**：普通 RL 可能压低罕见正确轨迹，未来 recipe 需要识别哪些问题适合强化、哪些需要保持 base 分布或增加探索。
4. **弱 base 的启动策略**：先蒸馏/行为注入再 RL，可能比直接 RL 更适合小模型；关键是找到从“缺知识”切换到“会但不会稳定用”的门槛。
5. **从可验证任务走向 agent 环境**：数学答案 verifier 相对干净，工具使用和长期任务的 reward 容易被钻空子，循环训练系统的瓶颈会从算法转向环境与评测设计。

## 📌 可执行结论

选择 RL 起点和评估 RL 结果时，至少建立五组独立指标：

1. 当前部署能力：pass@1、任务成功率。
2. 潜在覆盖边界：大 k pass@k、unique solved problems。
3. 探索状态：rollout entropy、正确轨迹多样性。
4. 环境进入能力：format/tool pass rate、协议遵循率。
5. 真实能力增长：过程正确性、held-out/OOD transfer、可解决难度上限。

若只出现 pass@1 上升，应称为“可用性提升”；只有过程正确性、覆盖边界或迁移难度也提升时，才有更强理由称为“能力扩展”。
